---
name: Состояние durable-запуска
description: Правила выхода из фонового восстановления и безопасного административного повтора.
---

Фоновый durable-запуск не должен оставлять защищённый модуль в промежуточном состоянии после исключения. Ошибка переводит запуск в отдельное конечное состояние, а повтор выполняет весь restore/reconcile, а не только последнюю сверку.

**Why:** Если исключение остаётся только в журнале, сохранённое `restoring` одновременно закрывает финансовые данные и запрещает оператору восстановиться без перезапуска приложения.

**How to apply:** Сериализовать старт и ручной повтор одним process lock, хранить только безопасный код этапа, держать потребителей остановленными до успешной сверки и запускать их идемпотентно после `ready`. В development согласовывать уже существующую локальную БД без полного App Storage restore; при публикации и ручном retry выполнять restore полностью. Пока production restore идёт, HTTP GET/HEAD должен отвечать лёгкой стартовой заглушкой без БД, чтобы routing probes не занимали worker threads; доступ открывать сразу после reconcile, не дожидаясь safety backup.
