---
name: Полное удаление предприятия
description: Гарантии аудита и файловой очистки при необратимом удалении предприятия.
---

Полное удаление предприятия допустимо только после архивирования и точного подтверждения названия администратором. Удаление записей из БД должно фиксировать намерение в аудите в той же транзакции.

**Why:** База может успешно удалить предприятие, а файловое хранилище — временно отказать. Нельзя терять аудит или сообщать пользователю, что всё удалено, если файлы остались.

**How to apply:** После транзакции очищать каталоги предприятия. При ошибке сохранять долговечный pending-статус, показывать неполный результат и автоматически повторять очистку; завершённым считать только состояние без ошибок.

### Восстановление вместо повторного создания

Восстановление архивного предприятия не должно переписывать его реквизиты или импортировать ОСВ как для нового предприятия. Сохранять прежний ID, данные и права; при неоднозначном совпадении останавливать операцию.

**Why:** Форма создания не является согласием заменить существующие данные. Обработчик первой загрузки рассчитан на новую запись и при ошибке может удалять её; применять этот жизненный цикл к восстановленной записи опасно.

**How to apply:** При совпадении восстановить только статус и явно сообщить результат. Файлы добавлять отдельной загрузкой в существующее предприятие; сообщать, если файлы из формы создания не импортированы. Совпадение имени не объединяет разные переданные юридические идентификаторы.
