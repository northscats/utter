---
name: Быстрый ответ фоновых операций
description: Как сочетать мгновенный ответ браузеру с долговечными снимками фоновой обработки.
---

Маршрут, который только сохраняет входные файлы и запускает фоновое задание, не должен выполнять общий тяжёлый резервный снимок до возврата ответа браузеру. Общая страховка после административных POST также должна выполняться одним сериализованным фоновым исполнителем с объединением накопившихся изменений. Снимки значимых этапов обработки делает worker после фактического сохранения данных.

**Why:** Синхронная страховочная копия после каждого успешного POST сначала задерживала редиректы, а серия административных изменений заняла все HTTP-потоки ожиданием App Storage. Порт продолжал слушать, но весь интерфейс перестал отвечать.

**How to apply:** Для новых фоновых операций явно отделять быстрый этап постановки в очередь от долговечных контрольных точек. Не выполнять общую safety-net копию в HTTP after-request. Перед пропуском общей страховки убедиться, что worker создаёт снимок после каждой значимой записи данных.

Тяжёлое резервирование не должно удерживать слот очереди разбора файлов: освобождать его после фиксации результата обработки, сохраняя немедленный запуск нужной резервной копии отдельно.

**Why:** В Лимитах резервирование уже обработанной выгрузки удерживало единственный слот, следующая оставалась в очереди без прогресса; повторные попытки лишь добавляли ожидающие потоки.

**How to apply:** Проверять очередь с намеренно заблокированным резервным транспортом: следующий файл должен обрабатываться. После удаления/ротации нужна копия, разрешающая ожидаемое уменьшение истории, а не обычная страховочная копия.

Процент обработки отражает измеренные этапы, а оценка оставшегося времени относится только к измеряемому этапу, не ко всему заданию. Не имитировать продвижение таймером.

**Why:** Пользователь попросил видеть реальный прогресс Лимитов. Скорость чтения строк не предсказывает длительность финансовой транзакции; запись прогресса не должна преждевременно фиксировать бизнес-данные.

**How to apply:** Обновлять контрольные точки с ограниченной частотой вне финансовых write-транзакций. При длительном применении сохранять процент этапа без выдуманной оценки времени.
