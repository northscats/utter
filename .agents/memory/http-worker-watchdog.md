---
name: Watchdog HTTP worker
description: Инварианты автоматического восстановления зависшего Gunicorn worker без дублирования фоновых задач
---

Проверку живости HTTP нужно выполнять из master-процесса реальным запросом к
лёгкому endpoint с тайм-аутом. Наличие PID и открытого порта не доказывает, что
HTTP-потоки способны отвечать. При тайм-ауте зависший worker завершается
принудительно штатным timeout-сигналом Gunicorn.

**Why:** фоновые IMAP и обработчики живут внутри процесса, а зависший worker
может продолжать числиться работающим. Параллельный запуск замены до завершения
старого процесса создаст дубли потребителей.

**How to apply:** сохранять ровно один Gunicorn worker; health endpoint не
должен обращаться к БД, App Storage или запускать фоновые потоки. Если
архитектура переходит на несколько worker, сначала вынести фоновые потребители
в отдельный координируемый сервис и только затем менять стратегию watchdog.
