# Работа с файлами лимитов

## Загрузка и контроль

Администратор открывает «Лимиты → Обзор и загрузки», указывает дату среза
и загружает XLSX. Создавать или выбирать набор не нужно, в том числе в пустой БД.
Общая таблица сохраняет файлы прежних независимых источников без их объединения.
Техническая последовательность выбирается сервисом: прежний источник MAX,
единственный существующий источник либо новая последовательность при неоднозначности.

Файл проходит очередь, разбор и сравнение автоматически. Страница обновляется
во время обработки; выбранный для загрузки файл не теряется при обновлении.
«Готово» означает, что снимок применён. У первой версии нет предшественника;
у последующих появляется ссылка на готовый отчёт и скачивание XLSX.
Исходный файл доступен отдельно. Повторная загрузка того же файла
не создаёт новую версию.

При ошибке таблица показывает причину, рабочие данные не заменяются.
При неоднозначности откройте отчёт и исправьте сопоставление. Дальнейшее
применение автоматическое: кнопки подтверждения документа нет.
Для старых незавершённых загрузок предусмотрено «Возобновить обработку».
Исправленный исходный файл следует загрузить заново. Контрольные количества
и предупреждения доступны по отдельной ссылке.

## Фиксированный источник MAX

Администратор выбирает «Версия файла» на вкладке «Бот MAX» и сохраняет её.
Селектор показывает номер, имя и дату только готовых версий. Загрузка новой
версии не переключает бота. Сведения, список объектов, изменения, Excel и
рассылки должны использовать сохранённый снимок, с прежними разрешениями
по УИН и фильтром года финансирования.

Смена версии отменяет устаревшие задания отправки. Сохранение источника не
запускает бота и не отправляет сообщения. Не используйте реальную массовую
рассылку для проверки обновления.

## Обновление, восстановление и хранение

После восстановления БД, до очистки истории и восстановления фоновых заданий,
старая настройка источника MAX однократно переносится на его готовую текущую
версию. Если источник не был настроен, произвольного выбора нет.
Настройка хранится в БД и входит в резервную копию; смена выбора запускает
планирование защитной резервной копии.

Обычное окно истории — 10 готовых версий. Выбранный снимок MAX и необходимые
для его отчёта данные защищены от ротации и удаления. Для удаления защищённого
снимка сначала явно смените источник бота. Исторические идентификаторы,
сравнения и одобренные УИН сохраняются.
После автоматической ротации обработчик сразу публикует резервную копию,
разрешающую удаление старых строк, и только затем обычную страховочную копию
новой загрузки. Ожидание часового обслуживания для сохранения нового файла
не требуется. При неудаче флаг необходимости такой копии сохраняется для повтора.

При недоступности истории используйте административную страницу восстановления,
а не обходите проверку готовности. После восстановления проверьте общую таблицу,
источник MAX, отчёт выбранной версии и отсутствие повторных применений.
Все операции изменения требуют административных прав и CSRF.

## Изолированная браузерная проверка (только разработка)

Из корня репозитория:

```sh
.pythonlibs/bin/python osv-dashboard/limits_browser_harness.py --port 8091
```

Стенд печатает каталог временной SQLite, файлов и синтетических XLSX.
Открыть `http://127.0.0.1:8091/login`, войти под
`limits-browser-admin` / `Browser-only-301!Pass` (одноразовая тестовая учётная запись).
Стенд не использует рабочую БД, реквизиты MAX или резервные копии;
исходящие сетевые соединения запрещены, операции запуска/отправки MAX заблокированы.
CSRF, авторизация, реальный XLSX-парсер и фоновое применение включены.

1. Открыть пустую таблицу, загрузить `snapshot-1.xlsx` с датой среза.
2. Дождаться «Готово» через обновление страницы; отдельного принятия нет.
3. В MAX выбрать #1 и сохранить.
4. Загрузить `snapshot-2.xlsx`, дождаться отчёта, открыть его и скачать XLSX.
5. Убедиться, что MAX всё ещё показывает #1, в том числе после обновления страницы.
6. Повторить загрузку второго файла: новой версии нет.
7. Загрузить `invalid.xlsx`: видна ошибка, готовые снимки не заменены.
8. `snapshot-3.xlsx` позволяет проверить ещё одно обновление без переключения MAX.

Для подготовки только файлов без запуска сервера используйте `--fixtures-only`.
После проверки остановите процесс и удалите напечатанный временный каталог.
