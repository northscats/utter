# Эксплуатация входящего канала 1С

Пользовательская инструкция встроена в Настройки → Интеграции → Интеграция с 1С.
Протокол и административные API: [one-c-api-contract.md](one-c-api-contract.md).

## Граница доверия

Gunicorn не преобразует forwarded-заголовки в доверенную WSGI-схему.
Внешний OneCTransportMiddleware фиксирует исходный peer и схему до legacy
ProxyFix. HTTPS признаётся при настоящем TLS на WSGI-соединении либо при
единственном `X-Forwarded-Proto: https` от непосредственно доверенного прокси.
`Forwarded`, `X-Forwarded-SSL`, цепочки `http, https` и заголовки недоверенных
адресов не дают разрешения. `X-Forwarded-For` не определяет доверенный peer.

Необходимо:

* `ONE_C_ENV=production` (значение по умолчанию): тестовый HTTP запрещён.
  `REPLIT_DEPLOYMENT=1/true` дополнительно запрещает обход независимо от
  ONE_C_ENV и переключателя канала.
* `ONE_C_PUBLIC_BASE_URL` — подтверждённый канонический HTTPS origin
  опубликованного приложения (при размещении в подпути включает этот подпуть).
  Без него production не выдаёт неподтверждённую ссылку.
* `ONE_C_TRUSTED_PROXY_CIDRS` — только реальные адреса непосредственного
  reverse proxy. В текущей Replit-конфигурации — loopback IPv4/IPv6.
  Не устанавливать `0.0.0.0/0`, `::/0` и не доверять клиентским заголовкам.
* Прокси обязан **перезаписывать**, а не дополнять X-Forwarded-Proto;
  прямой доступ клиентов к backend-порту должен блокироваться сетью.
* В изолированном тестовом развёртывании оператор явно задаёт
  `ONE_C_ENV=test` или `development`; администратор отдельно включает
  HTTP для нужного канала. Это не влияет на ограничения внешнего прокси.

Существующий SCRIPT_NAME/DispatcherMiddleware сохраняется. В workspace
более точный service path `/api/1c` направляется во Flask, тогда как `/api`
остаётся за существующим API Server. На самостоятельном сервере маршрут
`/api/1c/push/` должен попадать во Flask без изменения метода/тела/Authorization.

## Внешний прокси

Ограничьте тело до 8 МиБ для `/api/1c/push/`, время чтения тела (например,
`client_body_timeout 15s` в nginx) и частоту запросов. Ограничения приложения
защищают обработку, но не могут прервать зависшее сетевое чтение внутри WSGI.
Для production на HTTP возвращайте отказ, а не предлагайте отправителю
автоматически переносить Authorization на другой URL. Выдавайте отправителю
сразу конечный HTTPS URL.

Не включайте отладочную запись входящих тел/заголовков. Access log приложения
не включает query string, Referer или Authorization. Внешний proxy/APM тоже
должен скрывать эти поля. Пароль не хранится в восстановимом виде; его ротация
не меняет URL. Серверные ответы с реквизитами и данными имеют `Cache-Control: no-store`.

## Доступность

Проверка метаданных публикации 2026-09-08: приложение опубликовано публично,
тип — Autoscale. Новый код не становится опубликованным автоматически.
Проверка HTTP из среды разработки: TCP-соединение с портом 80 публичного
и preview-домена не установлено; это не доказывает, что HTTP недоступен из всех
сетей. До разрешения HTTP оператор должен проверить конечный маршрут из сети
1С **без реквизитов** и без следования перенаправлениям.

Круглосуточный обмен требует постоянно работающего развёртывания (Reserved VM
или эквивалентного сервера), исправной БД, маршрутизации, TLS и исходящего доступа
из сети 1С. Preview и масштабирование до нуля не являются гарантией постоянного
процесса. Существующая модель Gunicorn — один worker; не увеличивать число worker,
поскольку другие фоновые процессы приложения привязаны к одному процессу.

## Хранение и восстановление

Таблицы создаются аддитивно существующим `init_db`/`create_all`. Бизнес-данные
ОСВ не изменяются. Последний исходный JSON хранится в БД текстом без float/JSONB
преобразования чисел. Неуспех не заменяет снимок. Успех возвращается только после
commit. Снимки надо включать в обычные резервные копии всей PostgreSQL БД;
отдельный существующий защитный snapshot ОСВ не является резервной копией каналов.

Один канал защищён уникальным ограничением предприятия. Записи канала
сериализуются блокировками БД; ротация, отключение и приём согласованы.
Удаление предприятия удаляет и канал с его журналом/ключами.
Idempotency-Key действует 7 дней. Журнал — 30 дней и максимум 1000 записей
на канал; служебные записи очищаются лениво при обращениях. Содержимое старых
пакетов не архивируется. После удаления канала старые реквизиты не действуют.

## Сквозная проверка после публикации

1. Через настройки опубликованного приложения создать канал тестового предприятия.
2. Закрыть страницу администратора.
3. Из сети 1С отправить строгий однопредприятийный JSON с Basic Auth на
   выданный HTTPS URL; проверить HTTP 200 и receipt_id.
4. Повторить с тем же ключом, затем иным телом/тем же ключом (409).
5. Через настройки сверить последнюю таблицу и журнал; смешанный пакет
   должен быть отклонён без изменения снимка.
6. Перезапустить приложение и снова проверить снимок, затем ротировать пароль
   и проверить отказ старых реквизитов.

Не проверять передачу настоящих финансовых данных по HTTP и не создавать
фиктивные предприятия автоматически из входящего образца.
