# Контракт пилотного приёма JSON из 1С

Администратор создаёт канал только в «Настройки → Интеграции». Канал
принадлежит одному активному предприятию. Логин и URL можно посмотреть позже,
пароль возвращается только при создании или ротации и в базе хранится в виде
стойкого хеша.

## Отправка

`POST /api/1c/push/<channel-id>` использует HTTP Basic Auth. Реквизиты нельзя
помещать в URL или тело. В production разрешён только HTTPS. Тестовый HTTP
можно отдельно включить лишь в непроизводственном изолированном контуре; это
не отменяет ограничений внешнего прокси.

Тело — строгий UTF-8 JSON без BOM, повторяющихся ключей и текста после JSON:

```json
{"ErrorCode":0,"ErrorDescription":"","Result":[
  {"Организация":"Пример","ОрганизацияИНН":"1234567890","Период":"2026-09-01T00:00:00Z","Аналитика1":"01","Значение":-123.4500}
]}
```

Конверт содержит ровно `ErrorCode`, `ErrorDescription`, `Result`.
`ErrorCode` должен быть числовым нулём, описание — строкой, Result — массивом
объектов. Нулевое число строк корректно. Число строк, ключей и полей
`АналитикаN` переменно. Все непустые пакеты должны содержать только
`ОрганизацияИНН`, точно совпадающий с ИНН предприятия канала. Смешанный пакет
нужно заранее разделить по ИНН; предприятия сервер не создаёт.

Лимиты ресурса: тело не более 8 МиБ, глубина JSON не более 32, бюджет обработки
10 секунд, не более 60 попыток канала в минуту. Одновременно обрабатываются два
тяжёлых запроса; при 429/503 следует повторять с экспоненциальной задержкой.
Превышение отклоняется целиком, без усечения и частичной записи.

Необязательный заголовок `Idempotency-Key` (до 200 символов) хранится 7 дней.
Повтор с тем же телом возвращает исходный receipt_id, а с другим телом — 409.
Без ключа повтор является новым снимком. «Последний» определяется порядком
успешной фиксации, а не значением поля `Период`.

Машинный ответ всегда имеет UTF-8 JSON-конверт
`ErrorCode/ErrorDescription/Result`. Успех — HTTP 200; 400 означает
неисправимый формат/принадлежность, 401 — реквизиты, 403 — канал/транспорт,
409 — конфликт, 413 — размер, 422 — ошибку источника, 429 — частоту, 503 —
временную перегрузку.

## Административный API

Все маршруты требуют сессию администратора и CSRF:

* `GET|POST /settings/1c/channels`
* `POST /settings/1c/channels/<id>`
* `POST /settings/1c/channels/<id>/rotate`
* `GET /settings/1c/channels/<id>/data`
* `GET /settings/1c/attempts`

Просмотр данных использует `offset/limit` и
`column_offset/column_limit`. Переданный `receipt_id` закрепляет снимок:
если за время пагинации пришёл новый пакет, сервер отвечает 409. Ячейки имеют
вид `{kind,text}`; `missing` отличается от `null`, а исходная запись чисел,
включая конечные нули, сохраняется. Вложенные значения возвращаются безопасной
JSON-строкой. Каталог колонок строится по всем строкам, а `АналитикаN`
упорядочиваются по числовому суффиксу.

Журнал ограничен 1000 попытками на канал и сроком 30 дней; он не содержит Authorization, паролей
или тел запросов. Последний успешный снимок переживает рестарт; неуспешная
попытка его не заменяет. Для круглосуточного обмена требуется постоянно
работающее опубликованное развёртывание и доступный маршрут из сети 1С;
preview этого не гарантирует.

Служебные записи очищаются при обращениях. Глобальный защитный лимит —
300 запросов/минуту на процесс. Сверх него запись отказов агрегируется
не чаще раза в минуту; обычные ошибки пароля журналируются отдельно и не
расходуют квоту аутентифицированного канала. Просмотр снимка также использует
ограниченный пул обработки. Ошибки source/format не раскрывают текст источника:
в журнал попадает фиксированное безопасное описание, а не содержимое ErrorDescription.
