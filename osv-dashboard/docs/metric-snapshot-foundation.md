# Контур компактных снимков показателей: текущий этап

Реализован частичный контур снимков для экрана «Основные показатели».
Секционные запросы экрана читают подготовленный источник из БД и не открывают
исходные ОСВ в HTTP. Скалярные карточки стандартных периодов читаются из
актуальной опубликованной версии без полного пересчёта; до публикации они
рассчитываются из подготовленного источника. При отсутствии источника API
возвращает 503 и запускает его фоновую подготовку. Старый несекционный маршрут
сохранён для совместимости и может читать исходные файлы.

## Что работает

- `rebuild_metric_snapshots.py --company-id N` (или `--all`) строит снимок вне
  HTTP-запроса; обычные загрузки и изменения сопоставлений ставят предприятие
  в долговечную очередь автоматически. Для каждого доступного месяца, квартала и года используется
  **тот же** расчёт и набор настроек, что у текущего экрана.
- В PostgreSQL хранится отдельная версия с небольшими скалярными значениями
  карточек. Публикация переключает активный указатель одной транзакцией после
  успешного расчёта всех стандартных периодов и повторной проверки ревизии.
  Ошибка сохраняет предыдущую версию.
- Очередь объединяет изменения по предприятию и восстанавливает прерванное
  задание после перезапуска одного worker. Перед публикацией проверяются
  ревизия данных и поколение очереди; очередная загрузка не может быть
  затёрта расчётом, начатым раньше. Изменение `METHODOLOGY_VERSION` запускает
  фоновую пересборку старых публикаций при старте.
- `GET /analytics/summary?company_ids=3,4&metric_ids=revenue,cogs&granularity=quarter&from=2026-01-01&to=2026-03-31`
  читает только компактные строки активных снимков. Требуется вход и право
  доступа к **каждому** указанному предприятию. Компании без снимка отмечаются
  `not_built`; при очереди показывает `stale`, `building` или `failed` вместе
  с идентификатором последней успешной публикации. Отсутствие значения не
  заменяется нулём.
- Новая карточка со скалярным `id` и `value` подхватывается при следующей
  пересборке без отдельного изменения схемы. Пустое подтверждённое значение
  остаётся `null`: карточка видна с пояснением, а не исчезает и не становится нулём.

## Не реализовано на этом этапе

Дневные агрегаты и накопительные индексы для быстрого произвольного диапазона,
структурная сверка каждого снимка с авторитетным ответом на всём наборе данных,
исторически зафиксированный межфирменный срез и нагрузочная проверка на
60 предприятиях. Произвольный диапазон сейчас пересчитывается по сжатому
источнику из БД, а не по компактным дневным компонентам.
При статусе `stale`, `building` или `failed` значения относятся к последней
опубликованной версии, а не к новым входящим данным.

Снимки не содержат полный ответ или первичные файлы и не являются источником
для восстановления ОСВ. При необходимости их можно заново получить из
подтверждённых исходных данных. В рабочем окружении миграции `init_db`
добавляют недостающие таблицы и компактные метаданные без удаления строк.
