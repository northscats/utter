# Контур компактных снимков показателей: текущий этап

Реализован **ограниченный базовый слой**, не замена всему экрану «Основные показатели».
Текущий экран продолжает получать полный авторитетный ответ через
`/company/<id>/key-indicators/data` и при промахе своего кэша читает исходные ОСВ.
Никакого ускорения смены произвольного диапазона этот этап сам по себе не даёт.

## Что работает

- `rebuild_metric_snapshots.py --company-id N` (или `--all`) строит снимок вне
  HTTP-запроса. Для каждого доступного месяца, квартала и года используется
  **тот же** расчёт и набор настроек, что у текущего экрана.
- В PostgreSQL хранится отдельная версия с небольшими скалярными значениями
  карточек. Публикация переключает активный указатель одной транзакцией после
  успешного расчёта всех стандартных периодов и повторной проверки ревизии.
  Ошибка сохраняет предыдущую версию.
- `GET /analytics/summary?company_ids=3,4&metric_ids=revenue,cogs&granularity=quarter&from=2026-01-01&to=2026-03-31`
  читает только компактные строки активных снимков. Требуется вход и право
  доступа к **каждому** указанному предприятию. Компании без снимка отмечаются
  `not_built`; отсутствие значения не заменяется нулём.
- Новая карточка со скалярным `id` и `value` подхватывается при следующей
  пересборке без отдельного изменения схемы.

## Не реализовано на этом этапе

Автоматическая очередь и восстановление заданий после перезапуска, публикация
полного source snapshot, доказательства качества значений, дневные факты и
накопительные индексы, быстрый произвольный диапазон, секционный payload,
прогрессивная загрузка UI, исторически зафиксированный межфирменный срез,
автоматический backfill после изменения методики и проверка нагрузки 60 предприятий.
API показывает время публикации, **не** обещает, что снимок уже учитывает более
поздние загрузки. Перед оперативным использованием нужно наладить обновление
снимков по событиям изменения данных и явно показывать устаревание.

Снимки не содержат полный ответ или первичные файлы и не являются источником
для восстановления ОСВ. При необходимости их можно заново получить из
подтверждённых исходных данных.
