# Контракт модуля «Оповещение о лимитах»

## Парсер и сравнение

`limits_parser.py` предоставляет только чистые функции и не обращается к БД:

* `parse_xlsx(path) -> dict` возвращает `columns`, `rows`, `warnings`.
  `columns` имеют `key`, `label`, `category`, `year`, `source`; `rows` —
  `uin`, `row`, `cells`, где значение ячейки содержит `raw`, `value`, `kind`,
  `cell`.
* `compare_snapshots(old, new, resolutions=None) -> dict` возвращает
  `changes`, `issues`, `summary`. Каждый change должен быть сериализуемым,
  содержать УИН, категорию, поле и старое/новое значения; issues требуют
  явного решения оператора. Пустота и прочерк не являются нулём.
  Координата строки для решения — строго `<полный УИН>@<номер строки Excel>`,
  например `1000000850.1000000533@42`. `resolution_json` передаёт либо
  однозначную пару `old_row`/`new_row` (перенос), либо самостоятельное
  решение `{"old_row": "...", "action": "absent"}` или
  `{"new_row": "...", "action": "added"}`. Пары должны быть взаимно
  однозначны; несуществующие или уже сопоставленные координаты отклоняются.

Сервис хранит исходный JSON без преобразования чисел в float и передаёт
`resolutions` из `LimitComparisonResolution.resolution_json`.

## MAX-адаптер

`limits_max.py` является HTTP-адаптером без Flask/SQLAlchemy и состояния
пользователей. Сервис создаёт его с токеном только из защищённой настройки.
При пустом токене отправка запрещена, а UI показывает «MAX не подключён».
Никакая настройка webhook и никаких live-вызовов не выполняются автоматически.

## Границы сервиса

`limits_service.py` владеет транзакциями, доступом, очередью, идемпотентностью
событий, ограничением 10 принятых версий и экспортом. Публикация создаёт
задания в той же транзакции. До фактической отправки повторно проверяются
активные доступ и подписка. Результат HTTP MAX означает только «принято MAX».
