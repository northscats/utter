# ОСВ → Дашборд (МУП «КГХ»)

Веб-прототип: загружаете выгрузки оборотно-сальдовых ведомостей из 1С (.xls),
система разбирает их, проводит аудит-проверки и генерирует автономный
HTML-дашборд с двумя режимами («Обзор» для руководителя / «Детально» для
экономиста) и фильтром по месяцам.

## Состав

| Файл | Назначение |
|---|---|
| `app.py` | Flask-приложение: страница загрузки → протокол обработки → дашборд |
| `osvparser.py` | Парсер ОСВ 1С: .xls (xlrd) и .xlsx (openpyxl), восстановление иерархии аналитик по уровням группировки строк, контрольные проверки СН+Об=СК |
| `builder.py` | Сборка датасета: помесячный P&L, статусы закрытия месяцев, ДЗ/КЗ, ДДС, налоги, ФОТ, автогенерация резюме «Что происходит» |
| `templates/dashboard_template.html` | Шаблон дашборда (автономный, без внешних библиотек, графики — собственный SVG) с плейсхолдером `/*__DATA__*/` |
| `templates/upload.html` | Страница загрузки с drag-and-drop и протоколом аудита |
| `cli.py` | Вариант без веба: `python cli.py папка_с_осв -o dashboard.html` |
| `.replit`, `requirements.txt` | Конфигурация запуска |

## Запуск на Replit

1. Создайте Repl: **Create Repl → Import from… → Upload zip** (или создайте
   пустой Python Repl и перетащите все файлы проекта, сохранив структуру
   папки `templates/`).
2. Replit сам подхватит `requirements.txt` (flask, xlrd, openpyxl).
   Если нет — в Shell: `pip install -r requirements.txt`.
3. Нажмите **Run** (`.replit` уже настроен: `python app.py`, порт из `$PORT`).
4. Откроется веб-страница: перетащите .xls-файлы → «Построить дашборд».

Никаких секретов/ключей не требуется. Наружу ничего не отправляется —
вся обработка локальная.

## Запуск на своем сервере

```bash
pip install -r requirements.txt
python app.py                      # разработка, порт 8080
# продакшн:
pip install gunicorn
gunicorn -w 2 -b 0.0.0.0:8080 app:app
```

### DaData в закрытом сетевом контуре

Клиент DaData использует стандартные серверные переменные `HTTPS_PROXY`,
`HTTP_PROXY` и `NO_PROXY`, которые поддерживает Python `urllib`. Для
корпоративного центра сертификации задайте `SSL_CERT_FILE` (PEM bundle) либо
`REQUESTS_CA_BUNDLE`; для `urllib` гарантированно применяется `SSL_CERT_FILE`.
Не сохраняйте логин proxy или токен в исходном коде.

В карточке DaData администратор может настроить тайм-аут, число повторов,
начальную задержку и режим «Новое соединение на каждый запрос». Ответы 429 и
5xx, а также временные ошибки DNS/соединения/timeout повторяются с
экспоненциальной задержкой. Ошибки TLS и настройки proxy требуют исправления
конфигурации и повторно автоматически не отправляются.
Диагностический журнал различает авторизацию, лимит, DNS, соединение, timeout,
proxy и TLS. Исправление DNS, proxy, доверенного CA и firewall выполняется
инфраструктурной командой; приложение эти ограничения не обходит.

## Требования к выгрузкам из 1С

Отчет «Оборотно-сальдовая ведомость по счету», в настройках:

- **Группировка**: по субсчетам + аналитики (подразделения, статьи затрат,
  номенклатурные группы, контрагенты);
- **Периодичность**: «По дням» (иначе не будет помесячной динамики);
- Сохранение: «Сохранить как…» → **Лист Excel (.xls)** — важно сохранять
  средствами 1С, чтобы в файл попали уровни группировки строк.

Рекомендуемый набор счетов: 20, 25, 26, 50, 51, 60, 62, 68, 69, 70, 76, 90, 91.
Система устойчива к частичной загрузке — отсутствующие счета дадут пустые
блоки, протокол обработки об этом предупредит.

## Что проверяет аудит при загрузке

- файл является типовой ОСВ 1С (есть шапка «Счет»);
- контрольное равенство СН + Обороты = СК по каждому счету;
- дубли счетов в загрузке;
- наличие детализации по датам;
- статус закрытия каждого месяца (по оборотам 90.09/91.09 и 90.02):
  «закрыт» / «финрезультат не списан на 99» / «НЕ ЗАКРЫТ» — незакрытые месяцы
  подсвечиваются на дашборде и исключаются из резюме.

## Известные ограничения прототипа

- Макет ОСВ предполагает 6 колонок показателей (СН Дт/Кт, Об Дт/Кт, СК Дт/Кт)
  без колонок валюты/количества. Если в выгрузке включены доп. показатели —
  отключите их в настройках отчета.
- Ветка чтения legacy .xls (xlrd) написана по документации, но в среде
  разработки проверялась логика ядра на .xlsx-копиях тех же файлов. Если на
  каком-то .xls появится ошибка чтения — быстрый обход: пересохранить файл в
  .xlsx (Excel/LibreOffice) и загрузить его; ядро то же самое.
- Резюме «Что происходит» сформулировано под предприятие ЖКХ (тепло/вода);
  для другого профиля тексты в `builder.py` (функция `build_dataset`,
  блок `brief`) правятся в одном месте.
- Загруженные файлы складываются в `uploads/<timestamp>/`, готовые дашборды —
  в `output/`. Очистка — вручную или добавить cron.
- Авторизации нет: если сервер публичный, закройте доступ (Replit: приватный
  Repl / basic auth за reverse-proxy на своем сервере).
