Инструкция для администратора и специалиста 1С

1. Создание канала

Откройте «Настройки → Интеграции → Интеграция с 1С» и нажмите «Создать канал обмена данными». Выберите существующее активное предприятие с ИНН. Для предприятия разрешён один канал. Передайте специалисту 1С URL, логин и однократно показанный пароль по защищённому каналу связи. Система хранит только хеш пароля; забытый пароль можно только заменить. URL при замене не меняется.

2. Отправка строго одного предприятия

Внешний модуль 1С самостоятельно отправляет POST по расписанию. Используйте заголовки Authorization: Basic … и Content-Type: application/json; charset=utf-8. Реквизиты нельзя помещать в URL, параметры запроса или тело. У каждой строки «ОрганизацияИНН» должен точно совпадать с ИНН предприятия канала. Смешанный пакет отклоняется целиком; автоматического распределения и создания предприятий нет.

Присланный пример содержит 49 строк и 6 ИНН: для положительной проверки разделите его на 6 JSON-пакетов по ИНН, сохранив конверт каждого пакета. Исходный смешанный пример служит отрицательным тестом. Фраза после JSON в исходном TXT не является частью протокола и должна быть исключена при подготовке файла — приёмник не отрезает произвольный хвост.

{
  "ErrorCode": 0,
  "ErrorDescription": "",
  "Result": [
    {
      "Организация": "Пример предприятия",
      "ОрганизацияИНН": "1234567890",
      "Период": "2026-09-07T21:00:00Z",
      "Аналитика1": "03215643000000017301, Пример банка",
      "Аналитика2": "03215643000000017301",
      "Аналитика3": "Пример банка",
      "Значение": -123.4500
    }
  ]
}

Замените ИНН в примере на ИНН выбранного предприятия. Конверт содержит ErrorCode, ErrorDescription, Result. Дополнительные обязательные поля сверх образца не требуются. Result: [] — успешный пустой снимок. Количество строк и полей «АналитикаN» переменное, пропуски индексов допустимы. Новые ключи появляются в просмотре автоматически. «Значение» не трактуется как остаток или рубли. Передавайте ИНН и номера счетов строками, чтобы сохранить ведущие нули.

curl --request POST "$CHANNEL_URL" \
  --user "$CHANNEL_LOGIN" \
  --header 'Content-Type: application/json; charset=utf-8' \
  --data-binary @packet.json

Пример curl запросит пароль интерактивно; не записывайте его в историю команд. В плановом задании храните пароль в защищённом хранилище 1С. Не используйте --location, --location-trusted или отключение проверки сертификата. Перед передачей реквизитов проверьте конечный HTTPS URL без Authorization.

3. Ответы и повторы

После фиксации в БД возвращается HTTP 200: {"ErrorCode":0,"ErrorDescription":"","Result":{"receipt_id":"…","duplicate":false}}. Сохраните идентификатор приёма у отправителя. Без Idempotency-Key повтор заменяет снимок целиком, а не добавляет строки. Необязательный Idempotency-Key длиной до 200 символов действует 7 дней: тот же ключ и те же байты тела возвращают прежний идентификатор, а иное тело — HTTP 409. Повтор с ключом не возвращает старые строки поверх более свежего снимка. После 7 дней ключ может считаться новым. «Последний» означает порядок успешной фиксации, не значение «Период».

  • 400 — неверный JSON, конверт, ИНН, смешанный пакет или глубина. Исправить, не повторять без изменений.
  • 401 — неверные реквизиты. Проверить канал, логин и действующий пароль.
  • 403 — отключённый канал либо запрещённый HTTP. Исправить настройки/транспорт.
  • 409 — конфликт ключа или недоступное предприятие. Проверить причину; не менять ключ вслепую.
  • 413 / 415 — превышен размер / неверный тип содержимого. Уменьшить пакет / исправить Content-Type. Разделённые пакеты заменяют друг друга, не накапливаются.
  • 422 — источник прислал ненулевой ErrorCode. Исправить ошибку в 1С; последний успешный пакет не меняется.
  • 429 / 503, сетевой сбой, тайм-аут, прочие 5xx — повторить тот же пакет и тот же ключ с задержкой 5, 10, 20, 40… секунд (до 5 минут), случайным разбросом и учётом Retry-After. После нескольких неудач уведомить ответственного, не запускать бесконечный частый цикл.

4. Технические ограничения — не схема данных

Размер тела до 8 МиБ, UTF-8 без BOM, только строгий JSON: без повторяющихся ключей, NaN/Infinity и постороннего текста. Глубина JSON до 32 уровней, бюджет серверной обработки 10 секунд. Не более 60 обращений к каналу за минуту; общий защитный лимит 300 обращений за минуту на процесс и не более двух одновременно обрабатываемых пакетов. При превышении — явный отказ без усечения и частичного сохранения. Ограничение времени чтения медленного запроса дополнительно задаётся внешним прокси.

Ошибки пароля не расходуют квоту успешной аутентификации канала. После исчерпания общего защитного лимита журнал записывает не чаще одного события перегрузки в минуту со счётчиком подавленных попыток, чтобы шквал отказов не перегрузил БД. Это отдельное ресурсное ограничение журнала.

Хранится только последний успешный исходный пакет. Просмотр получает страницы строк и окна колонок, не загружая целиком пакет в браузер. Каталог колонок строится по всем строкам текущего пакета; аналитики сортируются по числовому индексу. Отсутствие ключа, null, пустая строка и ноль различимы. При новом пакете во время просмотра обновите снимок.

Журнал содержит до 1000 попыток на канал за последние 30 дней (для неизвестных каналов — отдельный общий лимит), без тел запросов, Authorization и паролей. Очистка выполняется при обращениях к интеграции; истёкшие записи могут физически оставаться до следующего обращения. Ключи идемпотентности хранятся 7 дней. Журнал — не архив содержимого.

5. Хостинг, HTTPS и проверка результата

Получение не требует открытой страницы или входа администратора. Для работы 24/7 нужен постоянно работающий сервер, доступная БД, маршрут /api/1c/push/… до Flask, действующий TLS-сертификат и доступ из сети 1С. Спящий preview этого не обеспечивает. Опубликованная среда на момент проверки использует Autoscale; для постоянно работающего процесса нужен Reserved VM либо отдельный постоянно работающий сервер. Изменения кода нужно опубликовать отдельно.

По умолчанию разрешён только HTTPS. «Разрешить HTTP для тестирования» применяется только к отдельному тестовому контуру с отдельными реквизитами, внутренней сетью/VPN или ограничением IP. При HTTP пароль и финансовые данные передаются открыто. В production HTTP запрещён независимо от переключателя. Приложение не отключает принудительный HTTPS внешнего прокси. Проверка 08.09.2026 из текущей точки не смогла установить соединение с портом 80; прямой HTTP из сети 1С не подтверждён. Перенаправления с Authorization не являются безопасным обходом.

После POST откройте этот же блок настроек, обновите список и нажмите глаз «Последние данные». Сверьте время UTC, число строк и идентификатор приёма с журналом. Первый успешный пакет доступен сразу — без мастера, сопоставления или ручного подтверждения. Страницы предприятий, ОСВ, рейтинги и действующая аналитика не изменяются.
